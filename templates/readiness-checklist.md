# Build Readiness Checklist

Use this before moving work from Definition or Planning into Build.

## Problem and Outcome

- [ ] Problem statement is clear.
- [ ] Business outcome is clear.
- [ ] Success metrics are defined.
- [ ] Target users or impacted groups are identified.

## Requirements

- [ ] Requirements are documented.
- [ ] Non-goals are documented.
- [ ] Acceptance criteria are testable.
- [ ] Edge cases and constraints are captured.

## Cross-Functional Alignment

- [ ] Product owner confirmed.
- [ ] Engineering owner confirmed.
- [ ] Business sponsor confirmed.
- [ ] Design owner confirmed, if needed.
- [ ] GTM owner confirmed, if needed.
- [ ] Support owner confirmed, if needed.
- [ ] Legal, compliance, privacy, or security review confirmed, if needed.

## Delivery Readiness

- [ ] Dependencies are known.
- [ ] Risks are documented.
- [ ] Milestones are realistic.
- [ ] Communication plan is defined.
- [ ] Product and Engineering agree the work is ready to build.

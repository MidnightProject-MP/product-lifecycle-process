# Change Proposal 0003: Ownership Matrix Review

## Problem

The ownership matrix needs clearer role accountability and richer notes that explain what each row is meant to answer.

## Proposal

Add a reviewed ownership matrix that:

- Uses one clear accountable owner per activity.
- Separates driver, owner, contributor, and informed roles.
- Interprets Product Owner as the Scrum Product Owner role, focused on backlog clarity, readiness, acceptance criteria, and sprint-level product decisions.
- Adds notes in question form so each row explains the questions it answers.
- Clarifies build readiness, technical requirements, release readiness, stabilization, and post-release feedback ownership.

## Expected Impact

- PMs can use the matrix as an operating guide, not just a static responsibility chart.
- Stakeholders can understand why each activity exists.
- Reviewers can spot unclear ownership or missing readiness earlier.

## Risks

- Some rows may need adjustment once local team titles and actual decision rights are confirmed.
- The matrix may need separate variants for small, medium, and high-risk initiatives.

## Adoption Notes

Review with Product, PMO / SME, TPM, Engineering, QA, and Release Management. After alignment, update the source Google Sheet or replace it with this repository-owned version.

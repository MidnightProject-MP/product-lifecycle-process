# Stray Story Prioritization

Stray stories are reviewed in the weekly prioritization meeting.

## Purpose

The weekly prioritization meeting prevents stray stories from becoming invisible work, unmanaged scope, or unowned backlog clutter.

## Inputs

Each stray story should include:

- Story title.
- Requester.
- Source.
- Problem or ask.
- Impacted user, customer, team, or system.
- Urgency.
- Expected value.
- Risk of not doing it.
- Known dependency.
- Suggested owner, if known.

## Dispositions

| Disposition | Meaning |
| --- | --- |
| Accepted | Approved for backlog ownership and priority placement. |
| Rejected | Will not be pursued. Rationale should be captured. |
| Deferred | Valid but not now. Review date or condition should be named. |
| Needs discovery | More problem clarification is needed. |
| Needs requirements | Business / non-technical requirements are not clear enough. |
| Attach to existing project | Story belongs under an active or planned project. |
| Convert to project | Story is large or complex enough to become a managed project. |
| Treat as bug / incident | Story represents unexpected behavior or production issue. |

## Weekly Meeting Outputs

The meeting should produce:

- Disposition.
- Owner.
- Priority.
- Next step.
- Due date or review date.
- Communication needed, if any.

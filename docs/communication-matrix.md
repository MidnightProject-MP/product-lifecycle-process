# Communication Matrix

The communication matrix defines when a work item update should create a communication candidate, what the message should contain, who should receive it, and whether the message can send automatically or requires review.

## Matrix Rule

Each row follows this structure:

```text
Lane + Trigger + Timing = What + So What + What's Next + Audience + Template + Send Rule
```

The matrix is designed for automation. A source-system update should be compared against the previous state, matched to a trigger row, logged as a communication candidate, and then sent, reviewed, bundled, skipped, or superseded.

## Severity

| Severity | Meaning |
| --- | --- |
| Low | Awareness only. No material action expected. |
| Medium | Stakeholders should pay attention or act during normal cadence. |
| High | Action, decision, or focused stakeholder attention is needed. |
| Critical | Leadership-level visibility, decision, or intervention is required. |

## Send Rule

| Send Rule | Meaning |
| --- | --- |
| Auto-send eligible | May eventually send automatically once trigger quality is proven. |
| Review then send | Message should be reviewed by the communication owner or phase owner before sending. |
| Approval required | Message requires accountable leader, decision owner, release owner, or risk owner approval before sending. |
| Log only | Record the event, but do not send unless bundled or escalated later. |
